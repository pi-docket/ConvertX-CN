# 環境變數設定測試指南

本文件說明如何驗證 ConvertX-CN 的環境變數設定與回退機制是否正常運作。

## 測試情境

### 情境一：完全沒有設定任何環境變數

**預期行為**：

- 系統正常啟動
- 使用 `pipeline` 模式處理 PDF
- 翻譯功能使用 `local` 引擎

**驗證方法**：

```bash
# 確保沒有設定任何環境變數
unset MINERU_MODE
unset BABELDOC_ENGINE
unset OPENAI_API_KEY

# 啟動服務
bun run dev

# 上傳 PDF 進行轉換，檢查日誌確認使用 pipeline 模式
```

---

### 情境二：設定 VLM 模式但 llama-server 不存在

**設定**：

```env
MINERU_MODE=vlm
```

**預期行為**：

- 系統嘗試使用 VLM 模式
- 偵測到 llama-server 不可用
- 自動回退到 `pipeline` 模式
- 顯示警告日誌但不中斷服務

**驗證方法**：

1. 設定 `MINERU_MODE=vlm`
2. 確保 llama-server 未安裝或不在 PATH 中
3. 啟動服務並上傳 PDF
4. 檢查日誌應顯示回退警告
5. 確認 PDF 仍成功轉換

---

### 情境三：VLM 模式正常運作

**前置條件**：

- llama-server 已安裝並可執行
- VLM 模型檔案存在於 `models/vlm/` 目錄
- Projection 檔案存在

**設定**：

```env
MINERU_MODE=vlm
VLM_MODEL_PATH=models/vlm/your-model.gguf
```

**預期行為**：

- VLM 服務啟動成功
- PDF 使用 VLM 模式處理
- 輸出品質較高

---

### 情境四：VLM 執行中發生錯誤

**測試方法**：

1. 設定 `MINERU_MODE=vlm` 並確保 VLM 可啟動
2. 開始處理 PDF
3. 在處理過程中手動終止 llama-server 進程

**預期行為**：

- 系統偵測到 VLM 失敗
- 自動切換到 `pipeline` 模式
- 當前任務繼續完成（可能需要重新開始該頁面）
- 後續任務使用 pipeline 模式

---

### 情境五：BabelDOC 翻譯引擎切換

#### 使用本地翻譯（預設）

```env
BABELDOC_ENGINE=local
```

#### 使用 OpenAI

```env
BABELDOC_ENGINE=openai
OPENAI_API_KEY=sk-your-api-key
```

#### 使用 DeepSeek

```env
BABELDOC_ENGINE=deepseek
DEEPSEEK_API_KEY=your-api-key
```

**驗證方法**：

1. 分別設定不同的翻譯引擎
2. 使用 PDF 翻譯功能
3. 檢查日誌確認使用正確的引擎
4. 驗證翻譯結果

---

## 日誌檢查重點

### 啟動日誌

正常啟動時應顯示：

```
[INFO] ConvertX-CN 啟動中...
[INFO] 處理模式: pipeline
[INFO] 翻譯引擎: local
```

### 回退日誌

VLM 回退時應顯示：

```
[WARN] VLM 模式啟動失敗，回退到 pipeline 模式
[WARN] 原因: llama-server 不可用
```

### 錯誤日誌

致命錯誤（不應發生）：

```
[ERROR] 無法啟動任何處理模式
```

## 環境變數完整列表

| 變數名稱            | 預設值     | 說明                              |
| ------------------- | ---------- | --------------------------------- |
| `MINERU_MODE`       | `pipeline` | 處理模式：pipeline 或 vlm         |
| `BABELDOC_ENGINE`   | `local`    | 翻譯引擎：local、openai、deepseek |
| `OPENAI_API_KEY`    | -          | OpenAI API 金鑰                   |
| `DEEPSEEK_API_KEY`  | -          | DeepSeek API 金鑰                 |
| `OTHER_LLM_API_KEY` | -          | 其他 LLM API 金鑰                 |
| `VLM_MODEL_PATH`    | -          | VLM 模型檔案路徑                  |
| `VLM_SERVER_PORT`   | `8080`     | VLM 伺服器連接埠                  |

---

## 故障排除

### 問題：系統無法啟動

1. 檢查環境變數格式是否正確
2. 確認 `.env` 檔案編碼為 UTF-8
3. 檢查是否有語法錯誤（如多餘的引號）

### 問題：VLM 模式無法啟動

1. 確認 llama-server 已安裝：`which llama-server`
2. 確認模型檔案存在
3. 檢查記憶體是否足夠
4. 查看 VLM 服務日誌

### 問題：翻譯功能不正常

1. 確認 API Key 設定正確
2. 檢查網路連線
3. 驗證 API 額度是否足夠
